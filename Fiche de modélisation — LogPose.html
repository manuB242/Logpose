Fiche de modélisation — LogPose

Document complémentaire au cahier des charges et à la fiche de développement technique. Il formalise le fonctionnement de LogPose à travers quatre modélisations : cas d'utilisation, modèle de données, scénarios de séquence et cycle de vie d'une session d'orientation.

1. Diagramme de cas d'utilisation

flowchart LR
  actorU((Utilisateur))
  actorIA((Assistant IA))

  UC1([Consulter le tableau de bord])
  UC2([Filtrer le marché de l'emploi])
  UC3([Explorer le catalogue des métiers])
  UC4([Consulter une fiche métier])
  UC5([Dialoguer avec l'assistant d'orientation])
  UC6([Obtenir des recommandations de parcours])

  actorU --> UC1
  actorU --> UC2
  actorU --> UC3
  actorU --> UC4
  actorU --> UC5
  actorU --> UC6

  actorU --> UC8
  actorU --> UC9
  actorIA --> UC5
  actorIA --> UC6

  UC2 -. inclut .-> UC1
  UC4 -. inclut .-> UC3
  UC6 -. inclut .-> UC5

Lecture : l'utilisateur est l'acteur principal de tous les cas d'usage. L'assistant IA intervient comme acteur secondaire sur la conversation d'orientation et le calcul des recommandations. Le filtrage (UC2) est une variante incluse de la consultation du tableau de bord (UC1) ; la consultation d'une fiche métier (UC4) découle de l'exploration du catalogue (UC3) ; les recommandations (UC6) s'appuient sur la conversation d'orientation (UC5).

3. Diagrammes de séquence

3.1 Consultation du tableau de bord avec filtres

sequenceDiagram
    actor U as Utilisateur
    participant App as Application mobile
    participant API as API backend
    participant Cache as Cache (Redis)
    participant DB as Base de données

    U->>App: Sélectionne période + filtres (zone, secteur, entreprise, type)
    App->>API: GET /dashboard?periode&zone&secteur&entreprise&type&n
    API->>Cache: Vérifie si le résultat est en cache
    alt Résultat en cache
        Cache-->>API: Données agrégées
    else Cache absent
        API->>DB: Requête d'agrégation (indicateurs, secteurs, top métiers, entreprises)
        DB-->>API: Données brutes
        API->>Cache: Met en cache le résultat
    end
    API-->>App: JSON (KPI, secteurs, top n métiers, top 5 entreprises)
    App-->>U: Affiche le tableau de bord mis à jour

3.2 Conversation d'orientation → recommandation de parcours

sequenceDiagram
    actor U as Utilisateur
    participant App as Application mobile
    participant API as API backend
    participant IA as Service IA
    participant DB as Base de données

    U->>App: Ouvre l'assistant d'orientation
    App->>API: POST /orientation/sessions
    API->>DB: Crée SessionOrientation (statut = Ouverte)
    API-->>App: session_id

    loop Échange conversationnel
        U->>App: Envoie un message
        App->>API: POST /orientation/sessions/:id/messages
        API->>IA: Prompt + historique de conversation
        IA-->>API: Question suivante / éléments de profil détectés
        API->>DB: Met à jour ProfilUtilisateur (série bac, intérêts, mode de travail)
        API-->>App: Réponse de l'assistant
    end

    U->>App: Sélectionne un métier cible
    App->>API: GET /orientation/sessions/:id/recommandations
    API->>IA: Calcul de compatibilité (profil + métier)
    IA-->>API: Liste de parcours scorés (Congo / international)
    API->>DB: Enregistre les Recommandation
    API-->>App: Parcours recommandés triés par score
    App-->>U: Affiche l'écran de recommandation
